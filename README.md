# tone-fix

[![release](https://img.shields.io/github/v/release/bahamoth/tone-fix)](https://github.com/bahamoth/tone-fix/releases) ![license](https://img.shields.io/badge/license-MIT-blue)

보고서, 슬라이드, 인포그래픽 같은 한국어 문서의 AI 말투와 번역체를 교정하는 스킬. 



교정 대상:

- **어휘와 구문**: "저희" 같은 1인칭, "발화했다" 같은 직역, "A 가 아니라 B 다" 같은 대조 강조, "근거가 수렴한다" 같은 의인화
- **구조와 가독성**: 본문을 줄여 옮긴 요약, 문제제기 없이 시작하는 본문, 정의 없이 쓰는 `L0~L5` 같은 코드, 3문장을 넘는 긴 문단
- **문맥**: 사실 뒤에 덧붙인 해석("이 전제가 설계를 결정한다"), 앞에서 한 말의 되풀이("이것이 ~ 계약이다"), 영어 숙어의 직역(source of truth → '진실 소스')

교정 방식:

- **알려진 표현**: 실제 리뷰에서 지적된 표현을 검출 규칙으로 만들어 자동으로 찾는다.
- **규칙에 없는 표현**: 문단마다 판별 질문을 던져 어색한 문장을 찾고, 그 문장은 구조부터 다시 쓴다.
- **교정 중 놓친 표현**: 교정을 마치면 작업 경위를 모르는 새 서브에이전트가 결과물만 읽고 남은 AI 말투를 찾는다.

## 3단계 파이프라인

| 단계 | 성격 | 검출 대상 | 도구 | 통과 기준 |
|---|---|---|---|---|
| 1단계 패턴 스캔 | 결정론적 | 1인칭, 가정형, 상투 제목, 수사의문문, `발화`, `~가 아니라`, `L0~L5`, `근거가 수렴`, `문제는 ~는 점이다`, `은퇴`, `더 잡는다`, `~은 셋이다`, `소음`, `원천`, `판단이 나온다`, `머릿속`, `—`, `·` 등 30종 | `scripts/check_lexical.py` | `hits: 0` |
| 2a단계 문장과 어휘 | 맥락 판단 | 미확정 단정, 동의어 중복, 의인화, 비전문가 어휘 | 규칙표 판별법 | 판별법 통과 |
| 2b단계 문단과 구조 | 맥락 판단 | 훅 없는 요약, 문제제기 절 누락, 정의 없는 단계, 결론이 아닌 절 첫 문장, 개수 예고 목록 도입 | 규칙표 판별법, `scripts/check_md_layout.py` | 판별법 통과 |
| 2c단계 문맥 판독 | 맥락 판단 | 구어 표현, 어울리지 않는 서술어, AI 조어, 낱말만 바꾼 핵심 문장, 의의 꼬리, 지시어 재진술, 꼬리표 판정, 명사화 사슬, 직역 숙어, 과장, 일반론, 문장 간 논리, 반복 | `scripts/sentence_sheet.py` 판독표 + 판별 질문 | 문단 전부 판독 |
| 3단계 가독성 | 결정론적 + 판단 | 훑어 읽기 어려운 긴 본문(900자 넘게 제목, 볼드, 표, 목록이 없음), 긴 문단, 볼드 남발, 리드 뒤 줄바꿈, 문장 경계 `<br>` | `scripts/check_md_layout.py`, `scripts/check_br.py` | `violations: 0` |
| 마무리 독립 판독 | 맥락 판단 | 교정한 에이전트가 놓친 AI 말투 | 교정 과정을 모르는 새 서브에이전트 + `references/review-prompt.md` | 지적마다 수용 또는 기각 사유 기록 |

2a~3단계에서 고치거나 독립 판독 지적을 반영한 문장에 새 위반이 생길 수 있어, 마지막에 1단계와 3단계 스크립트를 다시 실행한다.

## How It Checks

- **`check_lexical.py`**: 어휘 패턴 30종을 정규식으로 검출한다. `--honorific` 옵션을 지정하면 존대 문서에 남은 평어체 어미도 검출한다.
- **`check_md_layout.py`**: MD 문서에서 다음 위반을 검출한다. `X는 Y다` 형태의 리드는 `advisories:` 로 따로 센다.
  - 볼드 리드의 틀 문구(`문제는 ~는 점이다` 등), 연결 어미로 두 절을 이은 리드, 리드와 같은 줄에 붙은 부연
  - 형식에 맞지 않는 요약 항목, 문제제기 절 누락, 정의 없는 단계, 목록 앞 개수 예고 문장
  - 훑어 읽기 어려운 긴 본문(900자 넘게 제목, 볼드, 표, 목록, 코드 블록이 없음), 긴 문단, 볼드 남발
- **`check_br.py`**: HTML 의 `<p>`, `<dd>`, `<li>`, `<small>` 본문과 `innerHTML` 로 주입하는 인라인 `<script>` 문자열에서 문장 경계 `<br>` 누락을 검출한다.
- **`sentence_sheet.py`**: 문서를 문단(P)과 문장(S)으로 나누고 번호를 붙인 판독표를 만든다. 위반은 판정하지 않고, 읽으면서 세기 어려운 항목만 센다.
  - 본문에서 3회 이상 반복된 낱말(제목, 볼드 리드, 표의 낱말 제외)
  - 같은 절의 앞선 리드나 문단 첫 문장과 내용어가 절반 이상 겹치는 문장
  - '명사 + 다' 나 형용사로 끝나는 문장이 4개 이상 이어진 구간
- **독립 판독**: 새 서브에이전트에게 결과물과 [`references/review-prompt.md`](references/review-prompt.md) 만 주고, 판별 질문 여섯 개(삭제, 문어, 어울림, 역번역, 재진술, 근거)를 던지며 읽게 한다. 서브에이전트는 지적마다 문장 ID, 원문 인용, 판별 근거, 교정안, 확신도를 적는다. 교정한 에이전트는 지적마다 수용할지 정하고, 기각한 지적은 사유를 보고에 남긴다.

## Usage

문서, 슬라이드, 인포그래픽, 보고서를 쓰거나 마무리할 때 자동으로 활성화된다. 다음 요청으로도 트리거된다.

```
"이 문서 AI 말투 좀 고쳐줘"
"제목을 명사구로 바꿔줘"
"번역체 제거해줘"
"이 보고서 가독성 개선해줘"
```

스크립트 수동 실행(python3 표준 라이브러리만 사용):

```bash
python3 scripts/check_lexical.py report.md
python3 scripts/check_md_layout.py report.md
python3 scripts/check_br.py deck.html
python3 scripts/sentence_sheet.py report.md   # 판독표, 판정 없음
```

## Out of Scope

- 사실과 명제는 바꾸지 않는다. 다만 소스에 없는 세부 내용(방식, 시점, 동작)을 덧붙인 곳은 지운다.
- 맞춤법과 띄어쓰기 전반은 교정하지 않는다.
- 업계 표준 계층 용어(OSI L7, 알림 등급 L1/L2)는 교정하지 않는다.
- 통계와 수학에서 쓰는 '수렴' 은 의인화로 보지 않는다.
- 영어 인용문 안의 retired, kill 같은 원어 표현은 그대로 둔다.
- 현장에서 한자어로 부르는 용어(임계, 기준선, 지출, 노출)는 외래어로 바꾸지 않는다.

## Rules

규칙은 실제 리뷰 지적을 모아 만들었다. 독립 판독에서 찾은 표현이 여러 문서에서 되풀이되면 스크립트 검출 규칙에 추가한다. 규칙표에 인용한 지적의 예:

- "발화라는 단어 금지. 전형적인 AI 표현."
- "사람은 근거를 수렴한다고 표현하지 않는다."
- "XX 가 답하는 질문은 XX 가지다 → 사람은 이런 표현을 안 써."
- "소음이라는 직역보다는 노이즈가 자연스럽다."
