# Intent: UA 자동화 Level 1 알람 서비스

Author: BK (기술개발팀). Status: draft. 2026-09-17(목) 회의에서 PoC 를 공유한다.

| 항목 | 값 |
|---|---|
| 대상 | 라이브 타이틀의 UA 지표 이상을 매일 판정해 알람을 보내는 서비스 |
| 데이터 저장소 | MMP 웨어하우스(PostgreSQL) 그대로. 새 저장소 없음 |

## Problem

**라이브 타이틀의 UA 이상 감지가 담당자의 눈과 시간에 달려 있다.**

지표 감시는 UA 매니저가 대시보드를 매일 훑는 방식이다. 실측 백데이터에서 네트워크 지출 중단이 3주, 구매 트래킹 장애가 4일 지속된 사례가 있다 (R5).

**단순 임계 알람은 소음이 되어 무시된다.**

임계를 좁게 잡으면 하루 1건 이상 알람이 발화하고, 국가나 크리에이티브 단위까지 보면 스파이크가 전부 알람이 된다. 여러 게임을 맡은 담당자는 결국 무시하게 된다 (R1).

소음의 원천은 셋이다.

- 지출 급증 같은 의도한 UA 전환 뒤에도 이동 평균이 따라잡는 3~4일 동안 이어지는 연속 트리거 (R1)
- 소프트런칭 중인 앱에 매일 오는 "적자" 알람. 수익성을 목표로 하지 않는 시기라 조치할 것이 없다 (R12)
- MMP 가 노출 수를 받지 못한 소스의 CTR 급등처럼, 데이터 결함이 지표 이상으로 보이는 경우 (R4)

## Proposed outcome

**인수한 모든 타이틀에서 이상이 자동으로 감지된다.**

기본값은 설정 없이 동작한다. 기준선과 임계는 데이터에서 자동 산출한다 (R6). 앱마다 프로파일이 다르므로(LTV 지평, 마진) 게임별 override 를 허용한다 (R8).

검증에 쓰는 데이터는 두 가지다.

- 웨어하우스 수집 시작(2026-05-08) 이전 구간은 AppsFlyer API 로 가져온다.
- Meta Ad activities API 로 실제 집행 액션을 추적해 감지 신호와 대조한다.

## Affected users and systems

| 대상 | 영향 |
|---|---|
| 스튜디오 UA 매니저 | 알람을 받는 사람 |
| AppsFlyer API | 2026-05-08 이전 백데이터 원천 |
| Meta Marketing API(Ad activities) | 집행 이력 대조 원천 |
